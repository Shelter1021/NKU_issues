### 二、实验准备

#### **Cisco Packet Tracer**

Cisco Packet Tracer 是一款由思科公司开发的网络模拟软件，旨在帮助学习者、教育者和网络工程师进行网络设备的仿真、配置和测试。它提供了丰富的虚拟网络环境，使用户能够在无实际设备的情况下进行网络拓扑设计、配置交换机、路由器、防火墙等网络设备，并测试不同协议（如TCP/IP、OSPF、EIGRP、BGP等）的运行效果。

该工具的主要功能包括：

- 网络设备的配置和管理
- 模拟真实网络环境中的数据包流动
- 支持多种路由协议和网络层协议的实验
- 设备交互和连接的动态可视化

#### 3.4在仿真环境的“模拟”方式中观察数据包在共享式以太网中的传递过程，并进行分析。 ####

1. **切换到模拟模式**

   - 在软件右下角，把 **Realtime（实时模式）** 改成 **Simulation（模拟模式）**

2. **在 PC0 发 ping**

   - 输入：

     ```
     ping 192.168.1.14
     ```

   （或 ping 任意一台 PC 的 IP）

3. **观察数据包流动**

   - 回到主界面，会看到**事件列表**不断出现数据包（小信封）

   - 点击 **播放** 或 **逐步播放** 观察数据包流向

   - Hub 会将数据 **广播到所有端口**，不管是不是目标设备都会先收到

     <img src="C:\Users\xiexi\AppData\Roaming\Typora\typora-user-images\image-20251028195151155.png" alt="image-20251028195151155" style="zoom: 20%;" />

在 Cisco Packet Tracer 中切换至 **Simulation（模拟）模式**后，从 PC0 向其他主机发送 `ping`。通过模拟过程可以看到，**集线器 Hub 会将收到的数据包广播到所有端口**，所有连接的设备都会接收到数据包，即使不是目标主机也会收到，但只有目标主机才会回复。

这说明：

- 共享式以太网（Hub）属于**广播式通信**
- 数据包在网络中传播效率低，容易造成冲突

##### 和集线器的区别 #####

| 类型                 | 转发特点                                | 是否广播                   |
| -------------------- | --------------------------------------- | -------------------------- |
| **Hub（集线器）**    | 不判断目标设备，广播给所有端口          | 全部广播                   |
| **Switch（交换机）** | 根据 MAC 地址学习与转发，只发给目标端口 | 不广播（仅首次学习时泛洪） |

**原因：**

- PC0 属于 VLAN10，而 PC2 属于 VLAN20
- L2 VLAN **二层隔离，不经过路由器不能跨 VLAN 通信** 这个结果符合 VLAN 的隔离特性。

使用模拟模式观察发现，同一 VLAN 的主机可以正常通信，即使跨交换机，只要 trunk 链路允许对应的 VLAN。不同 VLAN 的主机二层隔离，数据包被交换机直接丢弃，不会被转发。

------

#### 3.10学习仿真环境提供的简化配置方式。 ####

在前面的任务中，我们使用命令行（CLI）方式对交换机与路由器进行 VLAN 划分、Trunk 配置以及路由器子接口配置。该过程虽然严谨，但步骤较多。

**在本任务中，我们使用 Cisco Packet Tracer 仿真环境提供的简化配置方式，通过图形界面完成配置，而不再输入命令。**

具体而言：

- 在交换机上，通过 *Config 界面* 直接将端口加入 VLAN，并将连接路由器的端口设置为 Trunk，无需 `switchport mode access/trunk` 等命令。
- 在路由器上，通过 *Add Subinterface（子接口）* 的图形化方式，为每个 VLAN 创建逻辑接口（例如 GigabitEthernet0/0.10、GigabitEthernet0/0.20），并在界面中直接绑定 VLAN ID 和对应 IP 地址，而不再使用 `encapsulation dot1Q 10` 和 `ip address ...` 等手工输入。
- 配置完成后，PC 即可通过不同 VLAN 与 Router-on-a-stick 通信，实现跨 VLAN 连通性。

结论：

**使用 Packet Tracer 简化配置模式，可以大幅减少命令输入量，更快完成 VLAN 与三层转发的实验搭建，同时依然保持逻辑正确性**。

### 四、实验总结

通过本次实验，我从最初对 VLAN、Trunk 与子接口配置完全陌生，到能够独立完成多交换机、多 VLAN 的组网，并最终通过路由器实现 VLAN 间通信。刚开始时，由于对交换机与集线器的区别、VLAN 的逻辑划分方式不够熟悉，导致出现了多次 ping 不通、数据包在交换机处被丢弃、接口没有设置为 trunk 等问题。特别是在第一次配置 Router-on-a-stick 时，我不清楚为什么只用一个物理接口就能够承载多个 VLAN，需要依靠子接口与 VLAN Tag 标记，也不知道必须为每台主机配置默认网关，因此实验过程中不断出现失败、重做和排查。

随着逐步理解 VLAN 是二层广播域隔离、Trunk 用于携带不同 VLAN 的数据、路由器子接口用于三层转发的原理后，我开始能够定位问题并正确配置设备。在 3.10 中使用 Packet Tracer 的简化配置方式（Config 模式）后，消除了命令输入的干扰，更直观地理解了网络逻辑，大大提高了搭建效率，也验证了理论与实际实验之间的对应关系。

本次实验让我意识到，网络设备配置并不是记住命令，而是理解逻辑：
 **先划 VLAN，再允许通过 Trunk，最后由三层设备完成跨 VLAN 通信。**
 经过不断尝试、验证与调整，我逐渐建立了对 VLAN 网络结构的整体理解，从最初的手足无措到能够独立完成配置，对网络分层结构和 VLAN 的工作原理有了更深刻的认识。
